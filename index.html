Section 1 · Building and managing programs 39%

The biggest section. It is really one question asked fourteen ways: what container do I use, and what plumbing has to be right for the reporting and the sends to behave?

1.1Identify when to use each of the 4 program types

Marketo has exactly four program types. A program is a container for a single marketing initiative — it holds the local assets (emails, landing pages, forms, smart campaigns, lists, reports) that belong to that initiative.

TypeChoose it whenIts unique capability
EmailOne-time blast — newsletter, promo, announcementBuilt-in A/B testing and the Email Program Dashboard
EventSomething with attendees at a specific date and time — webinar, tradeshow, party, roadshowWebinar-provider integration and check-in / attendance sync
EngagementOngoing nurture on a recurring cadenceStreams, casts, cadence, exhaustion, engagement score
DefaultEverything else — web forms, paid ads, social, scoring programs, or a parent shellTotal flexibility; no built-in send mechanics of its own

The decision test that works on exam questions: does the scenario need a mechanic only one type has? A one-time send that needs subject-line testing → Email. Attendance tracking from Zoom → Event. "Send the next piece of content every two weeks until they run out" → Engagement. Otherwise → Default.

Exam trap

Default is not "the leftover with no purpose". Adobe's own doc defines it as "anything that is not an event, engagement, or email program". A lead-scoring operational program, an online-ad program, a form-fill campaign — all correctly Default. Picking Email just because the program happens to send an email is the classic wrong answer.

1.2Why and when to use the Event program

An event program automates online or offline events — anything that has attendees at a specific date and time. Its value over a Default program is that it can talk to a webinar provider and to the check-in app, so attendance data lands in Marketo automatically instead of being imported by hand.

Event partners (LaunchPoint integrations)

Connecting an event partner lets Marketo: push landing-page registration data to the provider, pull attendance data back, and change program member statuses automatically. Providers with dedicated Adobe setup docs include Webex, Adobe Connect, ON24, GoToWebinar and Zoom. Marketo also has a native interactive-webinar capability where registrant and attendee data syncs without a third party.

The webinar progression statuses

When a program uses an event-with-webinar channel, the status set is fixed by the system:

Program Channel · Webinar
Not in Program ├─ Invited ├─ Pending Approval ├─ Wait Listed ├─ Rejected ├─ Registered ← system-required ├─ Registration Error ├─ Attended ← success status ├─ Attended On-demand └─ No Show

Refresh attendance manually with Click pathEvent program → Event Actions → Refresh from Webinar Provider

Exam trap

No Show can only be calculated for people who registered in Marketo. If someone signed up directly on the provider's page and never got a Marketo Registered status, Marketo has nothing to compare against and cannot mark them No Show.

Check-in app

The mobile check-in app marks attendees Attended in real time and requires an admin-granted role permission. A brand-new person created through the app is set to Registered; checking them in moves them to Attended. Only statuses mapped as the channel's Mobile Check-in Status for Registered and Attended appear in the app.

Availability

Adobe's own docs note that not every subscription has purchased event/webinar functionality. If an exam question hinges on "can they do this", assume the feature exists — but in real life confirm the licence.

1.3Why and when to use the Default program

Adobe's definition, verbatim: "A default program is anything that is not an event, engagement, or email program. Get creative."

The four jobs Default programs actually do in practice:

  1. Operational programs — lead scoring, lifecycle/MQL processing, data hygiene, alerting. These run on trigger campaigns and never "send a campaign" in the marketing sense.
  2. Content and acquisition programs — a gated asset with a landing page, form, thank-you page and follow-up email.
  3. Paid media and social — an online-ad program where the channel's statuses track clicks through to conversion.
  4. A parent container — a shell holding sub-programs or local assets used by several campaigns.

A Default program can also be used as content inside an engagement stream — you add the program to the stream and Marketo treats membership/success as the engagement signal instead of opens and clicks (see 1.4).

1.4Special features of the Engagement program

An engagement program answers a different question from every other program type: not "who should get this email" but "what is the next thing this person hasn't seen yet?" You load content into a prioritised stream, set a cadence, and Marketo works down the list per person.

Memorise

100 active engagement programs per subscription. That's a documented hard limit on active programs, not total.

Engagement score, precisely

  • Range 0–100, from a proprietary formula weighing engaged behaviour (opens, clicks, program success) against disengaged behaviour (unsubscribes).
  • Benchmarked so average drip/nurture content scores about 50, and comparable across all Marketo customers — not just your instance.
  • Calculated 72 hours after each cast, and covers only your last three casts.
  • When the stream content is a program rather than an email, the score is based on program membership and success status — opens and clicks are irrelevant.
Exam trap

Two very testable oddities. First: there is no trigger for exhaustion. To act on exhausted people you build a batch campaign filtering on Member of Engagement Program → Exhausted Content: true. Second: engagement programs ignore an email's Operational flag. Never put operational mail in a stream.

Declaring the winner

Winner criteria options are Opens, Clicks, Click to Open %, Engagement Score, or a Custom Conversion (any trigger-based event). Declaration mode is Automatic (Marketo sends the winner at least 4 hours after the test starts) or Manual (you get a results report and choose).

Exam trap

Two hard rules. A Date/Time A/B test can only use Manual declaration — Automatic isn't offered, because "which time won" can't be judged until both times have passed. And if you pick Engagement Score as the criterion, the test must run at least 24 hours. For champion/challenger, the Declare Date defaults to tomorrow, not today; until it arrives both versions keep sending.

On "control groups"

Marketo has no separate feature called a control group. If a question uses the phrase, it means the held-back portion of an A/B or champion/challenger split. Don't look for a Control Group object.

Head Start — making the send launch on time

By default the date/time you set on an email program is when the program begins processing. For a large audience that means emails trickle out after your chosen time. Head Start flips it: Marketo processes the program in advance so the emails actually launch at the time you picked.

Click pathEmail program → Schedule tile → set date/time → tick Head Start → Approve Program
Memorise
  • Processing begins approximately 12 hours before the scheduled time.
  • Once processing starts, the program is locked.
  • Head Start cannot be used with A/B testing.
  • With Recipient Time Zone also on, the 12 hours is measured from the earliest time zone (UTC +14:00), not yours. Adobe's worked example: from America/Los Angeles you must schedule 34 hours ahead — 22 hours of offset plus the 12-hour head start.

Approval tile statuses run: Waiting to run → Processing started, waiting to run → Processing finished, waiting to run → Finished. You can still hit Abort Program after lock but before the send.

Exam trap — the unsubscribe window

Anyone who unsubscribes after program lock will still receive the email. Adobe's documented mitigation is to word your unsubscribe confirmation to say opt-outs may take 1–2 business days to process. This is the compliance-flavoured consequence of Head Start and is very quotable.

Second rule: if you unapprove with less than 12 hours to go and then change your mind, you must pick a new date/time at least 12 hours ahead of when you re-approve.

Exam trap — reusing emails

Never reuse an email asset that has already sent from an email program — don't reference it from a smart campaign, don't move it to another program. All historical data is attached to that email's ID and will aggregate into every dashboard tied to it. To send similar content again, clone the email. Related: email programs can be nested inside Default programs, but cannot be nested inside engagement programs.

1.6Recognise what can be cloned

Click pathMarketing Activities → select program → Program Actions → Clone → choose destination folder or workspace

Cloning a program copies the program and all of its local assets. Two documented behaviours matter enormously:

Memorise — the 1,000 rule

If a static list inside the program you're cloning holds 1,000 or more people, the list clones but arrives empty. If it holds 999 or fewer, the list and its members both clone.

Memorise

Period costs do not transfer when a program is cloned. You must re-enter them on the clone. This is the single most-repeated clone gotcha.

Cross-workspace cloning

To clone into another workspace, every dependent asset the program relies on — email templates, landing page templates, snippets, images — must already be shared with the destination workspace. If a dependency isn't shared, the clone fails.

The practical rule the exam tends to probe: you cannot clone individual assets or smart campaigns directly between workspaces. The workaround is to put the item in a Default program and clone the program across.

Community-sourced, treat carefully

Community consensus, not stated on a single Adobe page: forms cannot be shared across workspaces (clone into a folder, move the folder); only a parent folder can be shared, not child folders individually; email templates, landing page templates, images, snippets, smart lists and segmentations are the asset classes that can be shared. Sharing behaviour depends on your workspace and partition setup, so verify in your own Admin.

1.7Benefits of custom tags

Tags are attributes that describe programs. Each tag type (e.g. "Program Owner", "Region", "Business Unit") has a set of selectable tag values. They carry no logic and no statuses — they exist so you can group and filter programs consistently.

Click path — createAdmin → Tags → New → New Tag (admin permission required) Click path — applyMarketing Activities → program → Setup tab → drag the tag onto the canvas → pick a value → Save

What you get for the discipline of tagging:

  • Filterable reporting — slice programs by owner, region, business unit, funnel stage.
  • Calendar filtering — see only the programs a given team or region owns.
  • Email Insights custom dimensions — program tags are one of the two things you can build a custom dimension from (segmentations are the other). See 4.3.
  • Governance — tag types can be made required for a program type, so nobody launches an untagged program.
Exam trap

Channel is a tag, but a tag is not a channel. Channel is a special tag type that additionally defines progression statuses and the success status. A custom tag is purely descriptive. Any question implying a custom tag drives member status is wrong.

1.8The purpose of channels

A channel is the delivery mechanism of a program — Webinar, Tradeshow, Online Ad, Email Blast, Sponsorship. Every program has exactly one. The channel is what turns a program from a folder into something measurable, because it supplies:

  1. Progression statuses — the steps a member moves through, each with a step number.
  2. A success status — the one status that means the program achieved its purpose.
  3. The program type it applies to — set at creation, and only one.

People cannot move backwards through progression statuses. They can only move to a status with a higher or equal step number.   • Event channels also need Mobile Check-in Status mappings for Registered and Attended for the check-in app to work.

1.9The importance of period costs

A period cost is the amount you spend on a program, entered per month, and it is what makes ROI reporting possible. Without it, Marketo can tell you how many successes a program produced but not what each one cost.

1.11Communication limits

Communication limits are the guardrail that stops one person receiving twenty emails in a week because five campaigns all qualified them.

Click pathAdmin → Communication Limits → Edit → set Per Day and Per 7 Days → tick "Block non-operational emails" → Save
Admin · Communication Limits
Per Day1

Per Day is based on the calendar day in the subscription time zone (midnight to midnight).

Memorise — exact mechanics
  • Two settings: Per Day and Per 7 Days. Presets, or Custom.
  • Per Day = the calendar day in the subscription's time zone, midnight to midnight. Not a rolling 24 hours.
  • The limits only actually block anything when "Block non-operational emails" is ticked. Untick it and they do nothing.
  • They automatically apply to all email programs and engagement programs.
  • The Admin value is the default. Individual smart campaigns and email programs can override it: Click pathSmart campaign → Schedule tab → Edit Settings → Block non-operational emails

The escape hatch: operational emails

Click pathEmail → Edit Draft → Email Settings → tick "Operational" → Save → re-approve the email

An operational email:

  • Ignores Unsubscribed and Marketing Suspended and sends anyway.
  • Does not count toward communication limits and is not blocked by them.
  • Is still blocked for Blocklisted people. Blocklist beats everything.
  • Is ignored inside engagement programs — a stream will not respect the flag.
Exam trap

Adobe's guidance is explicit: "You should only use operational emails for critical emails and auto-responders. They are not meant for marketing emails." Any answer that flags a promotional email operational in order to reach unsubscribed people is both wrong on the exam and unlawful in most jurisdictions.

1.12Program membership and acquisition

A member is a person who has a status in a program. That's the whole definition — no status, no membership.

The documented ways someone becomes a member

  1. Fills out a form on a landing page in that program → gets the first status in the progression automatically.
  2. Imported into the program from a CSV → also gets the first progression status automatically.
  3. The Change Program Status flow step in a smart campaign.
  4. Registers or attends a webinar synced to an event program.
  5. Created or checked in via the check-in app.
  6. Added to a synced Salesforce campaign linked to the program.
  7. For an email program: membership is created when the email is actually sent to the person — not when they qualify.
Exam trap

That last one catches people. Before the send, an email program has an audience but no members. This is also why Program Performance shows nothing for an email program that hasn't run.

Acquisition program — the one rule that matters

Memorise, verbatim from Adobe

"When a new name enters the system as a program member, Marketo automatically sets that program as 'acquisition.'"

Unpack that carefully, because the exam lives in the gap:

  • Acquisition is set only when the person is brand new to the database, at the moment of creation.
  • An existing person joining a new program does not get their acquisition program changed. It is effectively a one-time, immutable field.
  • Acquisition program is the mechanism behind first-touch (FT) attribution in revenue reporting.
  • To correct it after the fact there is no native button — you use a Change Data Value flow step on the Acquisition Program field, or a bulk backfill.

1.13Understanding customer preferences

Four person-level boolean fields govern whether someone is mailable. Getting these four straight is worth several questions.

FieldWho sets itWhat it blocks

Marketing SuspendedThe marketer — manually, by import, or Change Data Value. Marketo never sets it automatically.Marketing email. Operational still delivers. Intended as a temporary suspension.

Exam trap

Email Suspended stays ticked after the 24 hours elapse. The checkbox is historical; mailability is determined by Email Suspended At plus 24 hours. So "this person shows Email Suspended = true, why did they receive the email?" has a perfectly correct answer: the suspension window had expired.

Subscription / preference centres

A subscription centre is a Marketo landing page that lets people choose which categories of communication they want, rather than a blanket opt-out. It is not a turnkey feature — you build it from the pieces Marketo already gives you: boolean custom fields per subscription type, a form bound to those fields with pre-fill on, and a landing page. Then your marketing smart lists filter on those fields.

Durable unsubscribe

Marketo stores a master unsubscribe status in a separate table from the person record, applied across all partitions. Consequence: if you delete an unsubscribed person and later re-import the same email address, the unsubscribe persists — it isn't reset by record recreation.

Not documented as a native feature

Double opt-in is not a Marketo toggle. It's a pattern you build: form fill → operational confirmation email → confirmation landing page → Change Data Value to set the true opt-in field. If an answer option claims a built-in double opt-in setting, be suspicious.

1.14Best practices for review prior to launch

Adobe publishes a pre-launch QA process, and exam questions on this item tend to ask "what should you check before launching" with one plausible-but-wrong option. The checklist below follows the official structure. Read it as five gates.

Gate 1 — Program setup

  • Is the program type right for the use case?
  • Is the channel right, and do its statuses actually describe this journey?
  • Naming convention followed, so the program is findable in six months.
  • Period cost entered — even $0 — so the program appears in ROI reporting.
  • Success status identified, and a flow step exists that actually sets it.
  • Tokens tab checked — no leftover placeholder values from the program you cloned.

Gate 2 — Smart campaigns and audience

  • Smart list logic reviewed line by line; send count in the Schedule tab compared against expectation and against the abort threshold.
  • Exclusions in place — unsubscribes, blocklist, suspended — unless there's a documented operational reason not to.
  • Subscription-preference fields included in the logic.
  • Program status flow steps present, so membership and success get recorded.
  • Acquisition/attribution considered if this program will create new names.
  • Scoring and lifecycle impact considered — will this campaign accidentally MQL 8,000 people?
  • Communication limits applied to the campaign if there's a risk of collision with live nurture.
  • Legal basis to contact this audience confirmed. No purchased lists.

Gate 3 — Email asset

  • From name, from address, reply-to all confirmed with whoever owns that mailbox.
  • Subject line and preheader written deliberately; copy proofread.
  • Text version created and checked, with working links.
  • Every link clicked and every UTM verified; images compressed with alt text; nothing broken.
  • Dynamic content tested in every segment, including the Default segment.
  • Send Sample run, and inbox/rendering testing done.
  • Peer-reviewed by another Marketo user.

Gate 4 — Approvals

  • Every asset approved, nothing sitting in Draft or Approved-with-Draft.
  • For an email program, the program itself approved (a separate action from approving the email).
  • Champion/challenger tests approved.
  • Smart campaigns point at the correct assets.

Gate 5 — Go / no-go

  • Schedule and time zone confirmed; recipient-time-zone delivery decided.
  • Qualification rules correct (run once vs every time).
  • Stakeholder sign-off obtained.
Exam trap

3.5The purpose of a segmentation and its use

A segmentation is a set of mutually exclusive segments. Marketo evaluates every person against the segment rules in priority order, top to bottom, and assigns them to the first segment they match. Anyone matching nothing lands in Default. One person, one segment — always.

Segmentation · Region

Why it exists: dynamic content

Segmentations are the only thing that can drive dynamic content in emails, landing pages and snippets. A smart list cannot — because smart lists overlap, and dynamic content needs exactly one answer per person. That's the whole reason the object exists.

Memorise — two numbers people swap
  • Up to 100 segments inside a single segmentation (using standard fields).
  • Up to 20 segmentations per subscription — across all workspaces, not 20 per workspace.

Using custom fields, Member of List, person-owner fields or revenue stages increases rule complexity and may cause approval to fail well below 100 segments.

Approval lifecycle

  • The People (Draft) tab previews who qualifies before approval — a preview, not a guarantee.
  • The approved version stays live while a draft exists.

Exam trap — the operator restriction

"In Past" and "In Time Frame" are not supported in segment rules. The reason is mechanical: segmentation only re-evaluates a person when a Change Data Value activity is logged. Relative dates drift silently with no logged change, so Marketo would never notice. Relative windows are computed at approval time only.

Also unsupported in segmentation smart lists: SFDC Type and Microsoft Type filters. Account fields are discouraged.

Across workspaces

Segmentation processing runs only against people in the workspace where it was created. The recommended pattern is to create and approve it in a default workspace with visibility into all partitions, then put it in a folder and share the folder. Shared copies are read-only in the receiving workspace; only the original is editable. If the origin workspace can't see a target partition, it won't recalculate for those people.

3.11How triggers and filters work

This is the single most examinable idea in Section 3. Learn the sentence below well enough to recite it.

The rule

Triggers are always OR'd together. Filters can be AND, OR, or advanced logic. You cannot AND a trigger with anything — not with another trigger, and not with a filter.

How Marketo evaluates a trigger campaign
Trigger A ──┐ Trigger B ──┼── OR ──▶ did ANY fire? ──▶ then evaluate FILTERS Trigger C ──┘ │ Filter 1 AND Filter 2 AND … (or ANY, or advanced logic) │ ▼ FLOW
  • Triggers are initiating events: Fills Out Form, Clicks Link in Email, Visits Web Page, Data Value Changes, Person is Created, Campaign is Requested.
  • Filters are properties of the record right now: Country is US, Score at least 50, Member of List.
  • In a trigger campaign, a trigger must fire before filters are even considered. Filters are a second gate, not a co-condition.
  • Zero triggers = batch, automatically. Filter count and complexity are irrelevant to the classification.
Exam trap — the two-campaign answer

To express (Trigger1 AND Filter1) OR (Trigger2 AND Filter2) you must split it into two smart campaigns. One smart list simply cannot represent it. When a question describes logic that needs AND across triggers, "build two campaigns" is the right answer, not "use advanced logic".

Data Value Changes, and the import problem

The Data Value Changes trigger fires when a monitored value changes; the campaign then checks whether the specific attribute you configured was the one that changed.

Exam trap

Importing a CSV containing NULL values can generate spurious Change Data Value activity on numeric fields even where the field was already blank — which can falsely fire Data Value Changes triggers. Use constraints to prevent unwanted qualification during imports. This is a favourite troubleshooting scenario.

Trigger tokens — {{trigger.link name}}, {{trigger.new value}} and friends — let downstream flow steps reference details of the event that fired.

Not documented

No maximum number of triggers per smart campaign is documented. Multiple triggers are explicitly supported and OR'd. Any answer asserting "a smart campaign can only have one trigger" is wrong.

Email Performance's counting rules — worth reading twice

These are documented and unintuitive, which makes them good question material:

  1. Each activity record gets exactly one of: Delivered, Hard Bounced, Soft Bounced, or Pending.
  2. If it was Opened, it counts as Delivered.
  3. If it was Clicked or generated an Unsubscribe, it counts as Delivered and Opened.
  4. If Opened, bounces are ignored. If not opened, precedence is Hard Bounced > Soft Bounced > Delivered.
  5. No activity within 3 days of send → Aborted.
  6. Pending = Sent − (Delivered + Hard Bounced + Soft Bounced).
  7. Multiple sends of the same campaign to one person count once; sends from different campaigns count separately.
Exam trap

Clicking the unsubscribe link does NOT register under "Clicked Link". And the Unsubscribed column counts people who clicked the link and filled out the form — clicking alone isn't enough.

5.3Month-on-month and period comparison

This is the one your practice questions were circling, and the answer is counter-intuitive.

The answer

The basic Email Performance report cannot show month-over-month trending. It has exactly one time control — a single Sent Date filter on the Setup tab — and produces a flat table of emails for that one window. There is no group-by-period, no chart over time, and no built-in comparison.

For email trending over time you need Email Insights (date ranges plus a Compare to previous period, with a chart over time) or Advanced BI Analytics / Revenue Explorer (custom pivots and time dimensions). If the question is really about database growth rather than email engagement, the basic-report answers are People Performance (grouped by Created At month) or People by Status (explicit month-by-month rows).

The Setup-tab time frame and the Smart List tab are different layers: the time frame scopes which dates are included at all; the smart list additionally filters which people appear on top of that.

Practice questions

30 scenario questions in exam register. Answer before revealing — the explanation matters more than the letter.

Section 1 · Programs

1. A marketing team runs a monthly webinar series. Each month they need registration, reminder emails, attendance data from Zoom, and a report on registered-versus-attended. Which program type?
  • A. Default program
  • B. Email program
  • C. Event program
  • D. Engagement program
C — Event program. Attendees at a specific date and time, plus a webinar-provider integration that pulls attendance back automatically and changes program statuses. A Default program could hold the assets but would require manual attendance imports.
2. You cloned last quarter's webinar program. The invite went out naming the wrong date and speaker. What did you skip?
  • A. Approving the email program
  • B. Updating the program's My Tokens
  • C. Re-entering the period cost
  • D. Setting the channel
B — the Tokens tab. Cloning copies the local tokens with their old values. Checking the Tokens tab is an explicit item on Adobe's pre-launch QA checklist. (C is also true of clones, but it affects reporting, not email content.)
3. A webinar channel has Registered at step 2, Attended at step 3 and No Show at step 3. A person marked Attended is later found not to have joined. Can you set them to No Show?
  • A. No — progression is one-directional
  • B. Yes — the steps are equal, so movement between them is allowed
  • C. Only via a data value change on the status field
  • D. Only if the channel is unlocked in Admin
B. People can move to a status with a higher or equal step number. Giving Attended and No Show the same step number is exactly how you allow toggling. Had No Show been step 2, it would be impossible.
4. Communication limits are set to 1 per day and 5 per 7 days, but "Block non-operational emails" is unticked. A person qualifies for four marketing emails today. How many send?
  • A. One
  • B. Four
  • C. None
  • D. Depends on the channel
B — all four. The limits only enforce anything when "Block non-operational emails" is checked. Unchecked, they are effectively advisory.
5. A person unsubscribed last year. Marketing flags a promotional email as Operational so it reaches them. What's the correct assessment?
  • A. Valid — operational emails are designed to bypass unsubscribes
  • B. It works technically, but contradicts Adobe's documented guidance and likely breaks law
  • C. It won't send — unsubscribe always wins
  • D. It sends but counts against communication limits
B. Operational emails do ignore Unsubscribed and Marketing Suspended and do bypass communication limits, so it would send. But Adobe states operational should be used only for critical emails and auto-responders, not marketing. Any exam option endorsing this practice is the wrong answer.
6. An existing person in the database joins a new tradeshow program and reaches its success status. What happens to their Acquisition Program?
  • A. It changes to the tradeshow program
  • B. It is cleared
  • C. Nothing — it was set when they were created and doesn't change
  • D. It becomes multi-valued
C. Marketo sets acquisition only when a new name enters the system as a program member. For existing people it is effectively immutable — correcting it requires a Change Data Value on the Acquisition Program field. What they did earn is program success, which drives multi-touch credit.
7. Which two statements about period costs are both true?
  • A. They clone with the program; currency is set per program
  • B. They do not clone; currency is a global admin setting
  • C. They clone; currency is a global admin setting
  • D. They do not clone; currency is set per program
B. Period costs never transfer on clone, and currency is controlled globally by an admin, not per program. Enter costs as whole numbers, maximum 99,999,999.
8. A champion/challenger test is running. You declare a champion at 3pm on Tuesday and accept the default declare date. When does only the new champion start sending?
  • A. Immediately
  • B. Wednesday — the declare date defaults to tomorrow
  • C. After four hours
  • D. After 24 hours
B. The Declare Date defaults to tomorrow, not today. Until it arrives, Marketo continues sending both the old champion and the challenger(s).

Section 2 · Assets

9. A logo appears in 40 emails and 12 live landing pages. Brand ships a new version. What's the correct action?
  • A. Upload the new logo and update every asset
  • B. Use Replace image or file in Design Studio
  • C. Delete the old file, then upload with the same name
  • D. Create a snippet containing the logo
B — Replace. The URL stays identical, so all 52 assets update with no edits. Delete-and-reupload produces a new URL and breaks every reference. Note the replacement must be the same file type.
10. A form is embedded on your corporate website. Known visitors report that their details are never pre-filled. Why?
  • A. Pre-fill is disabled at form level
  • B. The fields are marked Sensitive
  • C. Pre-fill doesn't work on forms embedded outside Marketo landing pages
  • D. Munchkin isn't installed
C. Pre-fill only works when the form is placed on a Marketo landing page via Insert Element. Embed code never pre-fills. (B is a separate, real limitation — Sensitive fields never pre-fill anywhere.)
11. You fix a typo in an approved email and save. The campaign sends that afternoon. What do recipients see?
  • A. The corrected version
  • B. The original approved version
  • C. The send fails because a draft exists
  • D. Half get each version
B. In "Approved with Draft", the approved version is what sends. Your fix is invisible until you approve the draft. This is the most consequential rule in Section 2.
12. You update a global footer snippet and choose "Update all" at approval. What happens to the 30 approved emails using it?
  • A. Each becomes Approved with Draft and needs re-approval
  • B. They keep their approved status and reflect the new content immediately
  • C. They are unapproved
  • D. Only emails in the same workspace update
B. "Update all" pushes the change live without creating drafts — the assets keep their existing approval status. "Create drafts" is the option that generates 30 drafts needing individual approval.
13. A guided landing page needs its two-column hero changed to three columns. What's required?
  • A. Drag a third element onto the canvas
  • B. Switch the page to free-form
  • C. Edit the landing page template's code
  • D. Enable the mobile view
C. On a guided page you can only edit what the template exposes as editable. Layout changes mean code changes to the template. Free-form is the type where drag-and-drop layout changes are possible without code.
14. A "Text Only" email shows zero opens. Why?
  • A. Recipients blocked images
  • B. Open tracking is impossible without an HTML tracking pixel
  • C. The email wasn't approved
  • D. Text Only emails aren't included in reporting
B. An open is registered when the client downloads the tracking pixel. Plain text can't carry one. Links in text-only emails also aren't tracked automatically — they must be added as tracked links.
15. Which asset can be referenced from any program in the instance?
  • A. An email created inside a program via New Local Asset
  • B. An email created in Design Studio
  • C. A program-level My Token
  • D. A local static list
B. Design Studio assets are global and referenceable everywhere. Local assets are locked to their program; a My Token belongs to its program's context.

Section 3 · Audiences

16. You need: (Fills out form AND is in the US) OR (Clicks link in email AND score ≥ 50). What do you build?
  • A. One smart list with advanced logic
  • B. One smart list with ANY filter logic
  • C. Two smart campaigns
  • D. One campaign with a Choice step
C — two smart campaigns. Triggers are always OR'd and cannot be AND'd with anything, including filters. A single smart list simply cannot express trigger-specific filter pairings. This is the most testable rule in Section 3.
17. A trigger campaign fires for new people but never for people who qualified months ago. Most likely cause?
  • A. The campaign is deactivated
  • B. Qualification Rules are set to "only once"
  • C. A filter excludes them
  • D. Communication limits are blocking them
B. With "only once", anyone who has already run through the flow can never run again. Check Schedule tab → Edit Settings → Qualification Rules. Note this is a different setting from Schedule/Recurrence.
18. Qualified People shows 10,000. The send reports 9,300 delivered attempts. Is something broken?
  • A. Yes — the smart list is misconfigured
  • B. No — Qualified People ignores blocked people and communication limits
  • C. Yes — 700 records are duplicates
  • D. No — the difference is bounces
B. Qualified People is a preview of smart list qualification only. It does not account for unsubscribes, blocklist, suspended people or communication limits. The gap is expected.
19. You need email content to vary by region, for four regions, inside one email. What do you use?
  • A. Four smart lists and four emails
  • B. An approved segmentation driving dynamic content
  • C. A Choice step on the Send Email flow step
  • D. Four static lists
B. Only segmentations can drive dynamic content, because segments are mutually exclusive — dynamic content needs exactly one answer per person. It must be approved before it's usable. (C works but means maintaining four separate emails.)
20. A segmentation using "Filled out form in past 30 days" fails approval or behaves unpredictably. Why?
  • A. Too many segments
  • B. "In Past" isn't supported in segment rules
  • C. The segmentation isn't shared to the workspace
  • D. Form activity can't be used in smart lists
B. In Past and In Time Frame aren't supported in segment rules. Segmentation re-evaluates only when a Change Data Value activity is logged, and relative dates drift with no logged change — so Marketo would never notice. Relative windows are computed at approval time only.
21. A person should stop receiving one campaign's emails but stay in the database. Which action is wrong?
  • A. Remove from List
  • B. Change Engagement Program Cadence to Paused
  • C. Delete Person
  • D. Add them to a suppression list used by the campaign's filters
C. Delete Person removes them from the entire database, not one list or campaign. Note their unsubscribe status would still persist via durable unsubscribe even after deletion.
22. You import 5,000 people using "Skip new people and updates". A trigger campaign on Added to List never fires. Why?
  • A. The campaign is inactive
  • B. That import mode logs no activity at all
  • C. The CSV exceeded 100 MB
  • D. Trigger campaigns don't respond to imports
B. "Skip new people and updates" skips creating records, skips field updates, and logs zero activity — so nothing exists for a trigger to react to. Related trap in the other direction: a CSV with NULL values can generate spurious Change Data Value activity on numeric fields.
23. Which is NOT one of the six system smart lists?
  • A. Possible Duplicates
  • B. Bounced Email Addresses
  • C. People with no Munchkin cookie
  • D. Marketing Suspended
C. The six are All People, Unsubscribed People, Marketing Suspended, Blocklist, Bounced Email Addresses and Possible Duplicates. A "no Munchkin cookie" audience must be built manually. Only Possible Duplicates is editable.
24. A smart list has two filters. You want 1 and (2 or 3). What's needed first?
  • A. Switch logic to ANY
  • B. Add a third filter — advanced logic needs three or more
  • C. Nest a Member of Smart List filter
  • D. Nothing; advanced logic is always available
B. Advanced filter logic only becomes available at three or more filters. And when you do have the choice, Adobe recommends advanced logic over nesting Member of Smart List filters, for performance.
25. A Choice step on Send Email has: Choice 1 = Country is not empty → Email A; Choice 2 = Country is Japan → Email B; Default → Email C. What does a person in Japan receive?
  • A. Email B
  • B. Email A
  • C. Both A and B
  • D. Email C
B — Email A. Choices evaluate top-down and the first match wins. "Country is not empty" catches the Japanese person before Choice 2 is ever considered. Order your choices narrowest-first.

Section 4 · Reports

26. You need to know which specific CTA in last week's newsletter drove the most unique clickers. Which report?
  • A. Email Performance
  • B. Email Link Performance
  • C. Campaign Email Performance
  • D. Email Insights Sends
B. Email Link Performance breaks results down by individual link, with Clicks, % Clicks, People (unique clickers) and % People. Email Performance gives you only an aggregate Clicked Link count.
27. A Landing Page Performance report shows 4,200 conversions but the equivalent smart list returns 3,850 people. Which explanation is correct?
  • A. The report is stale
  • B. Landing Page Performance includes social and anonymous activity; smart lists filter only on People
  • C. Data retention purged 350 records
  • D. The report double-counts repeat submitters
B. Documented behaviour. As a bonus fact: Landing Page Performance data is retained indefinitely and is exempt from the activity retention policy — so C could never be the answer here.
28. A colleague wants to re-map an Email Insights custom dimension from "Region" to "Business Unit". What do you tell them?
  • A. Fine — edit it in Admin
  • B. Custom dimensions can't be deleted or replaced once assigned
  • C. Only after archiving historical data
  • D. You'd need to raise the limit above 10 first
B. You get ten, built from segmentations or program tags, and they are permanent. Remapping would blend old and new meaning and corrupt the history — which is why Adobe says "choose your 10 carefully."
29. Two programs each acquired one lead. Both leads sit at the same account, which produces one $100,000 opportunity. What multi-touch credit does each program receive?
  • A. $100,000 each
  • B. $50,000 and 0.5 opportunity units each
  • C. Only the first-touch program gets credit
  • D. Nothing until attribution is set to Implicit
B. This is Adobe's own worked example: each program receives 0.5 opportunity units and half the revenue. Credit is split, never double-counted. First touch is the acquisition credit to one program; multi touch is success credit shared across contributors.
30. A send finished two hours ago. The Email Program Dashboard shows numbers, but Email Insights shows almost nothing. What's happening?
  • A. Email Insights excludes email programs
  • B. Email Insights has up to 8 hours of latency
  • C. Data retention has purged it
  • D. The email was flagged Operational
B. Up to 8 hours for data to reflect in Email Insights. (Compare: Web Page Activity reports lag up to 24 hours — these two numbers are routinely swapped in answer options.) D is a real trap in a different scenario: operational emails are in Email Insights but hidden by default, toggleable in Personal Settings.
